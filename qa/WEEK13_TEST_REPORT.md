# Week 13 — отчёт по проверкам Stockroom

Прошли 45 Django-тестов, включая 19 сценариев Week 13. Проверены также сценарии предыдущих недель. Сборка Angular прошла на Node.js 24.22.3.

| Область | Проверенный результат |
| --- | --- |
| Сверка заказа | Принимает только ожидаемый SKU и нужное количество. Неизвестный код, лишний товар, превышение количества и повтор ID обработаны. |
| Прогресс и аудит | Повторное чтение API возвращает сохранённые количества, ячейку и автора. Отмена сохраняет автора исправления и возвращает ранее упакованный заказ в статус Confirmed. Сканам, принятым за один такт системных часов, назначается последовательное время для точной отмены последнего. |
| Отгрузка | Неполная сверка блокирует упаковку и отгрузку. После упаковки отгрузка списывает нужное количество один раз. Заказ из старой базы со статусом Packed тоже проходит сверку. |
| Поиск в чате закупок | Имя поставщика и номер закупки работают по отдельности и вместе. Читает сообщения по страницам в обе стороны. |
| Поиск сотрудников | Находит имена без учёта регистра, включая казахские буквы. Список исключает текущего пользователя, неактивные и внешние аккаунты. |
| Личный чат | Manager и Admin обмениваются сообщениями в одном диалоге. Другой сотрудник получает только свой диалог. Повтор POST с тем же UUID не добавляет вторую запись. |
| Модерация сообщений | В обоих чатах проверена базовая серверная фильтрация. Дополнительные тесты подтвердили словарь на 11 языках и распознавание растянутых букв, разделителей, маскировки звёздочками, подмен символов и невидимых Unicode-символов. HTTP 400 возвращается до записи. После исправления текст можно отправить. Обычные слова с похожими фрагментами проходят. |
| Роли | Представитель поставщика видит свои закупки. Внутренние сотрудники могут общаться друг с другом. Поставщикам и аккаунтам магазинов закрыт внутренний чат. |
| Восстановление | Тестовый почтовый backend получает письмо с кодом на привязанную почту. Ответ одинаковый для известного и неизвестного адреса. Слабый пароль, код другого адреса, просроченный и повторный код отклоняются. После смены пароля старые сессии перестают работать. |
| Миграция | Копия исходной `database/demo.db` обновлена до миграции Week 13. Двойной запуск `seed_week13` сохранил тот же демонстрационный заказ и закупку. |

В Chrome пройдены 15 экранов на русском и казахском. Проверены форма заказа, категории товаров, локальный формат дат, уведомления и сообщения об ошибках. В чате проверены отклонение растянутых и замаскированных ругательств и отправка обычного текста.

В Chrome отдельно проверены две сессии Manager ↔ Admin, поиск имени, обновление истории, отклонённый текст и его исправленная версия. В чате закупки сессия Supplier получила предупреждение, после чего исправленное сообщение появилось у Manager.

В Chrome пройдены сценарии сверки с обновлением страницы, отменой скана, упаковкой и отгрузкой. Отдельная проверка подала Code 128 через виртуальную камеру Chromium и подтвердила запись с источником `camera`. Чат проверен в двух отдельных сессиях, включая мобильный размер экрана. Проверено переключение на русский и казахский языки и сохранение тёмной темы после обновления. Сброс пароля пройден от формы запроса до входа с новым паролем по коду из локального тестового письма.

Дополнительно в Chrome проверены привязка почты в профиле, смена пароля по коду и сброс пароля с экрана входа на тот же адрес. Использовался локальный почтовый бэкенд. Тесты API также проверяют замену адреса двумя кодами, отказ при повторном использовании кода, уникальность адреса и сохранение текущего сеанса после смены пароля.

Реальный Gmail и физическая камера телефона требуют проверки в окружении демонстрации с настроенным отправителем и HTTPS.

Для повторного запуска тестов из корня проекта используйте Python виртуального окружения.

```text
python backend/manage.py test inventory --noinput
python backend/manage.py makemigrations --check --dry-run
```
