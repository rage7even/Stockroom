# Аксункар · API чата и восстановление · 24B031908

## Что показать

1. Откройте **Network**. В личном диалоге покажите `GET /api/chat/staff` и запросы к `/api/chat/staff/<staff_id>/messages`. В закупке покажите `/api/chat/<purchase_id>/messages`.
2. Для успешного POST покажите HTTP **201** и поля `request_id`, `body`. Объясните, что повтор того же запроса возвращает HTTP **200**, а тот же UUID с другим текстом или диалогом — **409**.
3. Покажите, откуда сервер получает отправителя и собеседника. Личный диалог выбирается по текущей сессии и ID сотрудника. Закупочный чат видят Manager/Admin и представитель привязанного поставщика.
4. Покажите, что перед записью и созданием диалога сервер пропускает текст через общий фильтр. При отказе возвращается HTTP **400**. Успешный сброс пароля проверяет код, меняет пароль и погашает код.

## Какой код открыть

| Файл и функция | Что объяснить |
| --- | --- |
| [urls.py](../../backend/config/urls.py) · маршруты `/api/chat` | Отдельные адреса закупочного и личного диалогов. |
| [chat.py](../../backend/inventory/chat.py) · `visible_purchases()`, `internal_colleagues()`, `direct_messages()` | Отбирает доступные закупки и действующих коллег. Для личного диалога сортирует два ID, чтобы обе стороны открывали один разговор. |
| [chat.py](../../backend/inventory/chat.py) · `checked_message()`, `save_message()`, `message_page()` | Общая проверка текста, идемпотентность по UUID и порционная загрузка истории. |
| [chat_moderation.py](../../backend/inventory/chat_moderation.py) · `check_message()` | Нормализует Unicode и регистр, учитывает повторяющиеся буквы, разделители и типичные подмены символов. Совпадения проверяются по словарю. |
| [recovery.py](../../backend/inventory/recovery.py) · `request_reset()`, `confirm_reset()` | Код отправляется на ранее привязанный адрес. Сервер хранит дайджест, ограничивает срок и число попыток. |
