## Подготовка

Из корня проекта, после установки зависимостей и сборки Angular, выполните команды с Python из виртуального окружения. На Windows путь может быть `.venv\Scripts\python.exe`, в WSL обычно `.venv/bin/python`.

```text
python backend/manage.py migrate
python backend/manage.py seed
python backend/manage.py seed_week11
python backend/manage.py seed_week13
```

Последняя команда готовит заказ с двумя зарядками и одним кабелем, создаёт закупку для чата и печатает их номера. Запускайте её на учебной базе. Повтор команды использует существующий незакрытый демонстрационный заказ или создаёт следующий после отгрузки, если хватает остатков.

| Учебный аккаунт | Логин |
| --- | --- |
| Менеджер Stockroom | `manager@stockroom.local` |
| Представитель поставщика | `supplier@stockroom.local` |
| Администратор для настройки | `admin@stockroom.local` |

Пароль для учебных аккаунтов — `Stockroom2026!`. Откройте Manager, Admin и Supplier в отдельных профилях браузера, чтобы три сессии работали одновременно.

### Как объяснить складской процесс

Клиентский заказ резервирует товар. Проверка подтверждает, что в коробку положили заказанные SKU в нужном количестве. Пока коробка на складе, физический остаток сохраняется. При отгрузке склад списывает товар и закрывает резерв одной транзакцией. Один и тот же SKU может быть у нескольких одинаковых единиц, поэтому новый скан считается отдельной штукой, а повтор сетевого запроса с тем же ID повторно не учитывается. При отмене последнего скана история хранит, кто и когда исправил запись.

Для демонстрации камеры на телефоне откройте приложение по HTTPS и используйте напечатанную этикетку Code 128. Поле штрихкода также подходит для ручного ввода и USB-сканера.

### Почта и пароль в профиле

1. Войдите в учебный аккаунт и откройте **Профиль → Безопасность аккаунта → Привязать почту для восстановления**. Введите адрес и текущий пароль, затем подтвердите полученный код.
2. Для смены пароля откройте **Изменить пароль**. После проверки текущего пароля Stockroom отправит код на привязанный адрес. Введите код и новый пароль дважды.
3. Выйдите из аккаунта и повторите отдельный сценарий через **Забыли пароль?** с тем же подтверждённым адресом. Для замены адреса в профиле нужны коды со старой и новой почты.

Встроенные демо-аккаунты позволяют самостоятельно привязать первую почту при локальном запуске через localhost. На опубликованном сайте первую почту для общего демо-аккаунта устанавливает администратор. Один адрес восстановления можно привязать к одному аккаунту.

### Как включить письма на Gmail

1. В **Django admin → Staffs** добавьте отдельный учебный аккаунт или откройте существующий. Запишите в **Verified recovery email** личный Gmail только после проверки, что адрес принадлежит владельцу аккаунта. Поле **Username** остаётся логином Stockroom. Для отображения ошибок и сброса используются разные формы входа.
2. Для HTTPS-отправки укажите `RESEND_API_KEY` и `STOCKROOM_EMAIL_FROM` от подтверждённого отправителя. Для SMTP укажите `STOCKROOM_SMTP_HOST`, `STOCKROOM_SMTP_PORT`, `STOCKROOM_SMTP_USER`, `STOCKROOM_SMTP_PASSWORD`, а также `STOCKROOM_SMTP_TLS=true` или `STOCKROOM_SMTP_SSL=true` по настройкам сервиса. Установите уникальный `DJANGO_SECRET_KEY` в окружении. Примените настройки перезапуском приложения.
3. Пользователь нажимает **Forgot password?**, вводит связанный Gmail, получает восьмизначный код, дважды вводит новый пароль и входит с обычным логином Stockroom. Для кода действуют срок в 10 минут, одна успешная попытка использования, максимум пять неверных вводов и пауза перед новым письмом.

В бесплатном Render используйте отправку через API по HTTPS. Для истории сканов, чата и смены пароля после перезапуска нужен постоянный диск или совместимая постоянная БД. В локальном Docker Compose SQLite сохраняется в томе `stockroom-data`.
