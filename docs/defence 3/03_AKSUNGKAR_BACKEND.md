# Аксункар · backend закупок и приёмки

**Твоя зона защиты** — API поставщиков, заказов и приёмки. Покажи правила, по которым Django принимает запрос, меняет статус заказа и обновляет физический остаток.

## Что показать

1. После скана Орена покажи, что в **Receive now** появилась 1 единица. Прочитай текущие **Already received** и **Still expected**. Это состояние формы перед сохранением.
2. Для заказа на 10 единиц поставь **Receive now = 6** и нажми **Confirm receipt**. Покажи **Partially received**, **Already received = 6** и **Still expected = 4**.
3. Введи **4** и подтверди вторую приёмку. Покажи **Received**, остаток по заказу **0** и две строки в **Receipt history**. Физический остаток теперь больше исходного на 10.
4. В **Network** открой первый POST на `/api/purchases/<id>/receipts`. Покажи вкладку Payload с `receipt_id`, SKU и количеством, а также статус **201**. Разбор отклонения и повторного запроса покажет Диас по тестам.

## Ответы на вопросы

| Вопрос | Короткий ответ |
| --- | --- |
| Что значит идемпотентная приёмка? | Одинаковый UUID, заказ, сотрудник и количества возвращают уже записанную приёмку с HTTP 200. Первая запись возвращает 201. Повтор того же UUID с другими данными возвращает 409. |
| Что если пришли два разных запроса по 6 на 10? | Записывающие транзакции выполняются последовательно. Второй запрос увидит 4 оставшиеся единицы и получит 409. |
| Что случится при ошибке после начала записи? | `transaction.atomic` откатит изменения текущей транзакции. Приёмка, складское движение и уведомления сохраняются вместе. |
| Что если товар отсутствует в выбранном заказе? | Проверяется принадлежность SKU; сервер отклоняет такой запрос с HTTP 400. |
| Когда заказ считается полученным? | Когда остаток к приёмке равен нулю по всем строкам заказа. |

**Передача слова.** «Две приёмки закрыли поставку. Диас покажет уведомления и проверки повторной записи, превышения количества и прав доступа».
